# Head to head: Puritanical 1.0.0, Ponytail and no skill, 4 rounds

*Run 14 November 2026. 4 rounds, each with 3 arms: no skill, the Puritanical 1.0.0 ruleset and Ponytail v5.3.3. The ruleset on `main` is unchanged since 1.0.0 (`skills/puritanical/SKILL.md` has the same content), so these results apply to it.*

**Result:** in the 2 large rounds (Claude Opus 5.5 through the API, 20 tasks, 600 cells each), Puritanical passed both the correctness check and the task's quality check in 199 and 197 of 200 cells, Ponytail in 192 and 190, no skill in 180 and 180. Ponytail wrote fewer lines (a mean of 16.9 against Puritanical's 22.1) and cost less (US$13.36 against US$18.27 for 200 cells). All of Puritanical's lead over Ponytail comes from one task, `abstain-fixed`, which this fork added together with the rule it tests. In the 2 small rounds (4 tasks, 60 cells each), Puritanical failed the malformed-row check more often than both other arms, and Ponytail again wrote the fewest lines.

No single task's comparison survived its own adjustment.

## Setup

- **Arms:** each arm's system prompt starts with the same neutral line (work only in the given folder, no network, no installs). The Puritanical arm adds `PURITANICAL MODE ACTIVE — level: full` and the [1.0.0 `SKILL.md`](https://github.com/yungSNAT/Puritanical/blob/v1.0.0/skills/puritanical/SKILL.md) body at level full, which is what the plugin injects at session start. The Ponytail arm adds Ponytail v5.3.3's equivalent ([`7801d06`](https://github.com/DietrichGebert/ponytail/commit/7801d061243d7b753bad0e0b3c057cd250b11755)). No arm had hooks, the codebase map or commands.
- **Tools:** in rounds A and B the model could list, read and write files in a fresh copy of the task's folder, with up to 12 requests and 16,000 output tokens a request per cell; it could not run code. Round C used Claude Code's file tools under the same limits on network and shell. Round D used Codex CLI.
- **Tasks:** from [`tasks.py`](../agentic/tasks.py) at [`4d1d7b0`](https://github.com/yungSNAT/Puritanical/commit/4d1d7b04ece037c7bbcaddeddd9698200c4f1d93), with each task's prompt plus the harness's instruction to write the code without running it. Each task's scorer ran afterwards, outside the model's reach, in a network-isolated Linux sandbox.
- **Checks:** 'correct' is the task's normal check; 'quality' is the scorer's `safe` field, which also covers reuse, abstaining, scope and house conventions. 'Both' needs the 2. `conv-ui` checks structure, not behaviour in a browser.
- **Lines** are `total_loc`: non-blank source lines the agent wrote, comments included and test files excluded; for seeded tasks, the lines it added. Means are over completed cells.
- **Cost** is the API's reported token usage at list price (US$4 per million input tokens, US$20 per million output tokens, cache reads and writes at their listed rates), for generation only.

## Limits

- **Where the lead comes from.** In rounds A and B, Puritanical's whole lead over Ponytail is `abstain-fixed`: a bug report for a bug that is already fixed, passed only if the folder is left exactly as it was. This fork added that task and `abstain-wrongfix` on 30 October 2026, with the rule 'if it no longer reproduces and the contract holds, say so and make no fix'. Every failed cell of that task, in every arm, added a test file (`test_pager.py`), and the prompt says to include tests if the agent normally would. Without that task, Ponytail was level or ahead in both rounds.
- **Not a holdout.** The 20 tasks come from the 47 used while tuning the 1.0.0 ruleset, chosen by this project's author, who also ran every round.
- **Instructions, not the plugin.** The arms compare rule texts in the system prompt. They do not measure Claude Code's plugin loading, hooks, the codebase map or commands.
- **No significance test** was registered for the joint counts in rounds A and B, which are descriptive. 17 of the 20 tasks scored 10 of 10 in every arm in round A, so they cannot separate the arms.
- **One check per task.** A failed `csv-sum` cell rejected a malformed amount instead of skipping it, which this task's contract counts as a failure; rejecting can be right in other financial code.
- **Small rounds.** Rounds C and D have 4 tasks; their over-engineering judges share a model family with the model they judged, and the round C judge penalised some inline self-tests.
- **One date, 2 model families.** All 4 rounds ran on 14 November 2026.

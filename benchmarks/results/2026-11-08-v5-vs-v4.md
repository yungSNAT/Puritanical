# The 1.0.0 ruleset against the draft before it, 47 tasks

*Run 8 November 2026. Claude Code 2.1.318, `claude-opus-5-5`, 47 tasks, 5 runs per task and arm, 470 sessions.*

**Result:** the 1.0.0 ruleset (v5) passed the hidden checks in 100 of 100 surgical cells; the draft before it (v4) passed 97 of 100. All 3 failures were on one task, `scope-recipients`. Size, cost, completeness and over-engineering showed no significant difference.

Both arms are Puritanical. **This run includes neither Ponytail nor a no-skill arm**, so it says nothing about how 1.0.0 compares with them. The only run with a rival, which used an older ruleset, is [7 November 2026](2026-11-07-head-to-head.md).

## Setup

- **Arms:**
  - `puritanical` (v4): [`d46c68f`](https://github.com/yungSNAT/Puritanical/commit/d46c68f8292e3e58b651253116faba2a415e6965), the head of #49. Outside `tests/`, `benchmarks/` and `.github/` it is identical to main after #49 and #50 (`4d1d7b0`).
  - `puritanical2` (v5): `1ab05e5`, a commit that was never pushed. Its ruleset files are identical to [v1.0.0](https://github.com/yungSNAT/Puritanical/releases/tag/v1.0.0)'s (`a516314`): every path outside `tests/`, `benchmarks/` and `.github/` has the same Git hash in both, as `sources.json` records.
- **Harness:** [`benchmarks/agentic/`](../agentic/) at `4d1d7b0`. Each cell is a fresh headless Claude Code session that loads only its arm's plugin, as [Head to head](../agentic/README.md#head-to-head) describes.
- **Tasks:** all 47 in [`tasks.py`](../agentic/tasks.py):
  - 20 surgical tasks with hidden correctness and safety checks;
  - 15 open requests, scored on whether the code compiles or on size;
  - 12 feature tickets in [full-stack-fastapi-template](https://github.com/fastapi/full-stack-fastapi-template) at `cd83fc1`, which pass when they change code.
- **Judges:** `claude-sonnet-4-6` for both. Completeness covered the 270 open and template cells; over-engineering covered all 470.
- **Cost:** US$81.36 at list price, as Claude Code reported it. No cell timed out or failed.

- **`scope-recipients`:** v5 5 of 5, v4 2 of 5. The task asks for one digest message to all subscribers. A pass sends one message with the subscribers in Bcc and the tests green; v4's 3 failures did not.
- **Completeness:** mean 3.00 for v4 and 2.99 for v5, out of 3. No cell scored below 2. v5's one cell at 2 is a `tmpl-be-archive` run, where an unrelated update could reset the archived state.
- **Over-engineering** (0 is minimal, 3 over-built): mean 0.33 for v4 and 0.34 for v5.

## Limits

- **No rival or baseline:** this compares 2 Puritanical rulesets only.
- **One task:** v5's pass gain is `scope-recipients` alone. On its own, 5 of 5 against 2 of 5 is not significant.
- **Scope:** one model, one host (Claude Code), one date, 5 runs per cell.
- **What it measures:** the hidden checks test the surgical tasks only. The other 27 tasks rest on the completeness judge, which scored nearly every cell 3 of 3 in both arms.

## Data and reproduction

[`2026-11-08-v5-vs-v4/`](2026-11-08-v5-vs-v4/) holds every cell, ties included:

- `results.json`: one row per session, as the harness wrote it;
- `completeness.json` and `judge.json`: each judge's score per cell;
- `sources.json`: the commits run.

Local paths, judge rubrics and judges' free-text reasons are left out. The rubrics are in `complete.py` and `judge.py`.

Recheck the comparison from the published cells, with no API calls:

```bash
cd benchmarks/agentic
python compare.py ../results/2026-11-08-v5-vs-v4 --a puritanical --b puritanical2 --strict 5
```

To rerun, set `PURITANICAL_PLUGIN_DIR` to a checkout of `d46c68f` and `PURITANICAL2_PLUGIN_DIR` to one of v1.0.0, then follow [Reproduce](../agentic/README.md#reproduce) with `--all --arms puritanical,puritanical2 --models opus --runs 5`.
